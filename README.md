# Pi 长日志预览实验

这是 Codex 和 DeepSeek 共用的本地项目。研究问题是：给 Pi 同等 token 预算的 bash 日志预览，保留头尾能否减少回读和整题成本，同时维持修复表现？

## 实验约定

| 组别 | bash 输出预览 |
| --- | --- |
| A | 使用固定版本 Pi 的默认策略 |
| B | 预算 T 内保留尾部，计入状态、提示和全文路径 |
| C | 同样预算 T，扣除状态、提示和全文路径后，头尾各用一半 |

主比较为同题 C 对 B。SWE-bench Verified 提供任务，官方评分器检查最终补丁。三组固定模型、Pi 版本和运行限制。记录每题的通过情况、token 用量、费用和日志回读。

## 当前进度

已核对本机 Pi 版本为 `1.6.0`。首个里程碑 M0 是跑通一题 A 组：在题目环境里执行测试，收集相对原始提交的补丁，在干净的独立容器用官方评分器评分。

## 当前分工和接口

- **DeepSeek 负责 `bench/`。** 选择并记录一个 SWE-bench Verified 试跑题号，搭建 runner、补丁收集和 grader。运行产物写到已忽略的 `runs/`。首条交接记录包括题号、base commit、Pi 版本与模型、实际执行的测试、补丁和官方评分报告的位置。通过或可解释的测试失败都能验证管线；环境故障单列。
- **Codex 负责 `extension/` 和该目录内的测试。** 在 Pi 的 bash 工具返回时生成 B/C 预览，校验预算、归档回读和退出状态。双方各自修改负责的目录，交叉审查对方的 diff。
- **Runner 接口。** 三组使用 Pi 1.6.0 和相同的模型、工具、隔离配置与运行上限。A 组用 `pi --no-extensions` 禁用扩展发现，保留标准工具。B/C 使用相同参数，另加 `-e /path/to/extension/index.ts`；该路径为约定入口，待 Codex 实现。用环境变量 `PI_PREVIEW_ARM=B|C` 选择策略，`PI_PREVIEW_TOKENS` 设置共用预算。路径应在 Pi 进程所在环境中可访问。正式评测前一起锁定模型、tokenizer 和 T。

## 两边怎么协作

两个助手都以本目录为项目根。开工前读取本文件并查看 `git status` 和 `git diff`。按上述目录分工；涉及双方的接口变更在 README 里交接。提交时只暂存自己负责的文件。
